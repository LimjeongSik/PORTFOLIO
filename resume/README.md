# resume/

포트폴리오 저장소의 내용(`src/data/*.ts`, `docs/PROGRESS.md`)을 바탕으로 만든 이력서 문서 모음입니다.
사이트 빌드와는 관계없고(Vite가 읽지 않음), Vercel에도 배포되지 않습니다.

| 파일 | 무엇 | 언제 고치나 |
|---|---|---|
| `index.html` | 디자인한 이력서. 브라우저로 열고 **PDF로 저장** | 레이아웃 · 스타일을 바꿀 때만 |
| `content.js` | `index.html`에 들어가는 **내용 전부** | 문구 · 경력 · 프로젝트를 바꿀 때 |
| `resume.md` | 긴 원고(경력기술서). 길이별 자기소개 · 프로젝트별 문제/해결/결과 | 지원서 칸에 붙여 넣을 글이 필요할 때 |
| `evaluation.md` | 저장소를 근거로 쓴 평가 · 보완점 · 면접 예상 질문 | 이력서를 다듬기 전 체크리스트로 |
| `assets/` | 배경을 뺀 프로필 사진 · 앱 아이콘 (`src/assets`에서 가져옴) | 사진을 바꿀 때 |

## 보는 법 · PDF로 저장

`index.html`을 더블클릭해서 브라우저로 엽니다(서버 필요 없음). 오른쪽 위 **PDF로 저장** →
인쇄 창에서 대상 "PDF로 저장", 용지 A4, **배경 그래픽 켜기**(타임라인 색이 나오도록),
머리글/바닥글 끄기. 지금 내용으로 **A4 4쪽**이 나옵니다. 경력 항목은 통째로, 긴 프로젝트는 사례 단위로만 쪽이 나뉩니다.

한글 서체(Pretendard)는 사이트가 구워 둔 `../src/assets/fonts`의 파일을 읽으므로 오프라인에서도 됩니다
(폴더를 저장소 밖으로 옮기면 CDN으로 넘어갑니다). 숫자용 Space Grotesk만 Google Fonts에서 받습니다.

## 내용 고치기 (`content.js`)

- 문자열만 바꾸면 됩니다. 쉼표 · 따옴표만 깨지지 않게 주의하세요.
- 기간은 `"2024.08 — 2025.05"` 또는 `"2025.04 — 현재"` 꼴. 타임라인 막대와 "1년 6개월" 같은 기간,
  상단의 **총 경력**이 이 값에서 자동으로 계산됩니다("현재"는 여는 날짜 기준).
- `"TODO"`로 시작하는 값은 화면에서 주황 점선으로 보이고 **PDF에서는 숨겨집니다**.
- `education` · `extras`는 비워 두면 섹션이 사라지고, 채우면 나타납니다(형식은 파일 안 주석 참고).
- 프로젝트의 `org`를 채우면 역할 옆에 소속이 붙습니다. `icon`은 `assets/`의 앱 아이콘이고, 없으면 브랜드 색 위에 첫 글자가 들어갑니다.
- 사진은 `profile.photo`(3:4 비율, 배경을 투명하게 뺀 PNG 권장), 이름 아래 한 줄은 `profile.current`입니다. 비워 두면 그 칸이 사라집니다.
- 연락처는 한 줄로 늘어놓고, 값이 길어 넘치면 다음 줄로 내려갑니다.
- 순서를 바꾸면 화면 순서도 바뀝니다. 지원 방향에 맞게 프로젝트 순서를 바꿔 쓰세요
  (`evaluation.md` 4장 참고).
- 경력의 `short`는 타임라인 막대 위 이름표입니다. 막대 진하기는 순서로 자동으로 정해집니다(오래될수록 옅게).
- 기술의 `core: true`는 굵게 표시됩니다.
- `sideProjects`는 "외주 프로젝트" 목록입니다(제목 · 설명 · 선택으로 `role` · `tech`). 비우면 섹션이 사라집니다.
  2026.09에 비웠습니다 — 되살리려면 git 히스토리를 보세요.
- 경력의 `achievements`를 비우면 그 경력은 한 줄짜리 간결한 행으로 그려집니다(옛 경력용).

## 편집 원칙 (2026.09 외부 비판 반영)

- **4~5쪽을 넘기지 않습니다.** 이력서는 다 보여 주는 문서가 아니라 고르는 문서입니다. 깊은 설명은
  포트폴리오 사이트로 넘깁니다.
- 첫 장은 출발점(웹 퍼블리셔)이 아니라 **지금 무엇을 해결하는 사람인지**로 시작합니다. 태그라인은 태도 문장이
  아니라 실제 일하는 방식입니다.
- **경력에는 조직 안의 역할과 영향, 프로젝트에는 기술 문제와 해결** — 같은 이야기를 두 번 쓰지 않습니다.
  테스트 개수 같은 수치도 한 번만 씁니다.
- 수치는 채용 판단에 의미 있는 것만 남깁니다(렌더링 1,300.9ms → 32.6ms처럼). 챗봇 도구 개수 · 번들 크기 같은
  숫자는 뺐습니다.
- OS 동작이 걸린 문장에는 조건을 붙입니다("근무 중", "Android는 ~"). 조건 없이 세게 쓰면 면접에서 공격받습니다.
- 기술 목록은 "지금 무엇으로 뽑아야 하나"를 보여 주는 것만. 한 번 써 본 것(Recoil · Three.js · GSAP 등)은 뺐습니다.
- 행사 참석(우아콘)과 생년월일은 뺐습니다. 포트폴리오 사이트도 프로젝트 목록에서 뺐습니다(연락처의 링크로 충분).
- 사실을 모르는 칸은 지어내지 않고 `TODO`로 둡니다 — 화면에서만 보이고 PDF에서는 줄째 숨겨집니다.

## 디자인 메모

- **힘을 준 곳은 한 군데**: 첫 장의 타임라인. 머리(사진 · 이름 · 연락처 · 타임라인)는 상자나 배경색 없이
  여백과 얇은 선으로만 가릅니다 — 머리만 색을 달리하거나 테두리를 두르면 이질적이고 답답했습니다.
  타임라인은 실제 기간 비율대로 그립니다(경력 막대는 최근일수록 진하고, 프로젝트 막대는 앱의 브랜드 색).
  경력 막대와 연도 축은 회색이 아니라 본문 먹색과 같은 보랏빛 계열(`--career-old` ~ `--career-new`)이라
  프로젝트 색과 한 화면에서 어울립니다. `sideProjectsSpan`의 외주 구간은 개별 날짜를 모르므로 점선으로 그립니다.
- **간격은 여덟 단계만** 씁니다(`--s1` 4px ~ `--s8` 64px). 섹션 사이 64px, 제목→내용 32px, 항목 사이 48px,
  문단 사이 16px. 본문 줄 간격은 1.8입니다. 간격을 고칠 때는 새 값을 만들지 말고 이 단계 안에서 고르세요.
- 사진 열과 본문의 왼쪽 열은 같은 폭(`--rail`)이라, 이름과 본문 내용이 한 세로선 위에 섭니다.
  소개의 핵심 역량도 이 오른쪽 열 안에서 한 장씩 쌓습니다 — 칸을 나누거나 왼쪽 열까지 넓히지 마세요
  (좁은 칸은 읽기 어렵고, 넓히면 정렬 축이 뒤틀립니다). 쪽수가 넘치면 글자가 아니라 여백에서 줄입니다.
- 사진(`assets/profile.png`)은 원본(`src/assets/profile.png`)의 크림색 배경을 투명하게 뺀 것이라 어느
  테마에서든 종이색이 비칩니다. 사진을 바꾸면 배경도 다시 빼야 합니다(단색 배경 사진이면 가장자리에서
  이어진 배경만 지우는 방식으로 충분합니다).
- 본문은 흰 종이에 두 개의 정렬 축 — 왼쪽 열에 섹션 제목 · 기간, 오른쪽 열에 내용.
  프로젝트 제목 옆에는 실제 앱 아이콘을 둡니다.
- 서체: 포트폴리오 사이트와 같은 체계 — 한글은 Pretendard, 기간 · 연도 · 수치는 Space Grotesk.
  세리프(Hahmlet)는 딱딱하고 읽기 어렵다는 피드백으로 걷어냈습니다. 색은 프로젝트에만 씁니다.
- 화면에서는 시스템 설정에 따라 어두운 화면이 되고(버튼으로 전환), **출력은 항상 흰 종이**입니다.
- 타임라인이 자라나는 애니메이션은 한 번뿐이고, 동작 줄이기 설정에서는 꺼집니다.

## 사이트 내용과 맞추기

`content.js`는 사이트 데이터를 복사한 것이지 연결된 것이 아닙니다. 사이트의 `src/data/*.ts`를 고쳤다면
이쪽도 손으로 맞춰야 합니다. 반대로 여기서 다듬은 표현(예: 띄어쓰기, 경력 성과 문장)을 사이트에도
반영하고 싶다면 `src/data/experience.ts`를 고친 뒤 `bun run knowledge`를 실행하세요.
