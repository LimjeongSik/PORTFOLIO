# 리뷰 받고 타당하면 반영하기

Codex는 실제 버그와 함께 거짓 양성, 이 프로젝트의 규약과 충돌하는 취향, 범위 밖 제안을 섞어 낸다.
이 스킬의 가치는 리뷰와 반영 사이에 **Claude의 판단 게이트**를 두는 것 — **코드가 진실의 원천**이고,
지적이 그럴듯해도 코드로 확인되지 않으면 반영하지 않는다.

## 1. 리뷰할 변경 확인

```bash
git rev-parse --is-inside-work-tree 2>/dev/null && git status --short --untracked-files=all
```

변경이 전혀 없으면 멈춘다. 추적되지 않은 새 파일도 리뷰 대상이다(`git diff`가 비어도 진행).

## 2. Codex 리뷰 실행

**반드시 아래 형태 그대로** 호출한다 — 이 커맨드 형태여야 Bash 자동승인 규칙
`Bash(bash .claude/scripts/codex-review.sh:*)`에 매칭되어 승인 프롬프트 없이 돈다. 인라인
`CODEX_SCRIPT="$(...)"; node` 형태는 변수 할당+서브셸이 섞여 매칭되지 않는다.

```bash
bash .claude/scripts/codex-review.sh review --wait
```

- `--wait`로 포그라운드 실행 — 결과를 받아 같은 흐름에서 판단·반영해야 하므로.
- 인증/설정 오류가 나면 `/codex:setup`을 안내하고 멈춘다(이 스킬은 설정을 대신 하지 않는다).
- 설계 자체를 도전적으로 검토받고 싶다는 신호가 있으면 `review` 대신 `adversarial-review`.

## 3. 각 지적을 판단한다 (핵심)

해당 파일·라인을 **직접 읽어** 대조한다. CLAUDE.md와 `docs/PROGRESS.md`의 규약·결정사항·함정 노트를
판단 기준으로 함께 참고한다.

**반영** — 세 가지를 모두 만족할 때: ① 지적이 사실이다(코드에서 확인) ② 이 코드베이스에서 실제
결함이거나 분명한 개선이다 ③ 수정이 안전하고 이번 작업 범위 안이다.

**미반영(이유를 남긴다)** — 하나라도 해당할 때:

- 코드와 대조했더니 틀린 지적이다.
- 프로젝트의 의도된 규약과 충돌한다 — Biome 설정과 어긋나는 스타일 취향, 의도적으로 둔
  `biome-ignore`나 reduced-motion용 `!important`를 문제 삼는 것, 데이터 분리 같은 아키텍처 결정을
  되돌리라는 제안.
- 범위를 크게 벗어나는 재설계다 → "후속 제안"으로 기록만.
- **판단이 애매하면 반영하지 말고 사용자에게 묻는다.** 확신 없는 자동 반영이 이 게이트의 취지에
  가장 어긋난다.

## 4. 반영 & 검증

판단을 통과한 것만 최소 침습적으로, 주변 코드 스타일에 맞춰 반영한다. 이후:

```bash
bun run check:fix && bun run build
```

둘 다 통과해야 마무리. 실패하면 고치고 다시 검증한다.

## 5. 보고

`docs/PROGRESS.md`의 관련 섹션을 갱신하고(프로젝트 규약), 지적별 처리를 표로 투명하게 보고한다:

```
| 지적 | 판단 | 처리 |
|------|------|------|
| <요지> | 타당 | 반영 (파일:라인, 무엇을) |
| <요지> | 거짓 양성 | 미반영 — <코드와 대조한 근거> |
| <요지> | 규약 충돌 | 미반영 — <어떤 규약과 왜> |
| <요지> | 범위 밖 | 후속 제안으로 기록 |
```

반영이 있었다면 check/build 결과를 함께 알린다. 사용자에게 불편한 지적이라도 사실이면 솔직하게
반영·보고한다.
