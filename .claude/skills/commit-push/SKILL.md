# 검증된 변경만 커밋·푸시하기

불변 규칙 하나: **리뷰와 검증을 통과하지 않은 변경은 GitHub에 올리지 않는다.** 어느 게이트든
실패하면 즉시 멈추고 무엇이 왜 막혔는지 알린다. "일단 올리고 나중에 고치자"는 없다.

## 준비 — PROGRESS.md 갱신 (게이트 전에)

게이트를 돌리기 **전에** `docs/PROGRESS.md`를 이번 반영 기준으로 갱신한다. 이유:

- **리뷰·검증·커밋 트리 일치** — 뒤로 미루면 게이트가 본 트리와 실제 커밋되는 트리가 달라진다.
- **자동 리뷰 훅 재발동 방지** — PROGRESS 편집도 마커를 남기므로, 같은 커밋에 담아 푸시 후 트리를
  clean으로 만들어야 Stop 훅의 git-status 가드가 재발동하지 않는다.

"마지막 검증"에 적을 결과는 게이트 2에서 실제로 확인된다. 게이트 2가 실패하면 코드를 고쳐야 하므로
트리가 바뀌고, 그건 정상적으로 다시 리뷰 대상이 된다.

## 게이트 1 — 리뷰 수행 확인

요구하는 것은 리뷰가 **수행·판단되었는가**이지, 지적이 **반영되었는가**가 아니다.

- 현재 변경을 대상으로 `review-and-apply`가 이미 돌았다면 통과.
- 안 했거나 **리뷰 이후 코드를 또 바꿨다면** 먼저 `review-and-apply`를 실행한다.
- **아무것도 반영하지 않은 리뷰도 통과다** — 전부 거짓 양성·규약 충돌·범위 밖으로 판단했다면 그것도
  정당한 리뷰 결과다.
- 단, 리뷰 중 **사용자에게 물어볼 보류 항목**이 남아 있으면 정리되기 전까지 푸시하지 않는다.

## 게이트 2 — 검증 통과

```bash
bun run check && bun run build
```

둘 다 통과해야 한다. 포맷 문제면 `bun run check:fix` 후 재실행하고, 그 수정도 새 변경이므로 게이트
1의 "리뷰 이후 변경" 여부를 재확인한다. 하나라도 실패하면 커밋/푸시하지 않는다.

## 게이트 3 — 시크릿 안전 확인

```bash
git status --short --untracked-files=all
git ls-files --error-unmatch .env .mcp.json 2>/dev/null && echo "위험: 시크릿이 추적되고 있음"
```

`.env`(GITHUB_PAT)·`.mcp.json`(API 키)·키/토큰류가 목록에 보이면 **중단**하고 사용자에게 알린다.

## 커밋 & 푸시

세 게이트를 모두 통과했을 때만 진행한다.

1. **커밋 단위 결정** — 먼저 `git status`로 변경 목록을 훑어, 성격이 다른 변경(사용자가 직접 편집한
   콘텐츠 + 코드 수정, 서로 무관한 작업)이 섞여 있는지 본다. 섞여 있으면 커밋을 나누고, 나눌 때는
   `git add -A`가 아니라 **커밋마다 해당 경로만 선택적으로 스테이징**한다. 한 덩어리면 `git add -A`로
   충분하다. 어느 쪽이든 `git status`로 담긴 목록을 눈으로 확인하고, 준비 단계에서 갱신한
   `docs/PROGRESS.md`는 코드 변경과 같은 커밋에 포함한다.
2. **커밋** — 무엇을 왜 바꿨는지 한 줄 제목 + 필요시 본문. 끝에 공동저자 트레일러를 포함한다(모델명은
   시스템 프롬프트에 명시된 현재 모델을 쓴다):

   ```bash
   git commit -m "$(cat <<'EOF'
   <제목: 한 줄 요약>

   <본문: 필요 시 무엇을/왜>

   Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>
   EOF
   )"
   ```

   단, **사용자가 직접 작성한 변경만 담긴 커밋에는 공동저자 트레일러를 넣지 않는다**(사실과 다르므로).
3. **푸시** — `git push origin HEAD`. 원격이 없으면 푸시하지 않고 설정을 안내하고, 인증 실패면
   커밋은 로컬에 남았음을 알리고 자격 증명 확인을 안내한다.
4. **보고** — 커밋 해시, 푸시된 브랜치/원격, 통과한 게이트를 요약한다. **이 단계에서 파일을 더
   수정하지 않는다** — 추가 편집이 생기면 자동 리뷰 게이트가 다시 발동한다.

## 브랜치

개인 포트폴리오 저장소라 현재 브랜치(`main`) 직접 푸시가 기본이다. PR 흐름을 원하거나 보호된
브랜치라면 사용자에게 확인 후 새 브랜치 + PR로 전환한다.
